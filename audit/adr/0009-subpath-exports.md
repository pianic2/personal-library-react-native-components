# ADR 0009: Subpath exports

## Status

Proposed. It records decision D7 (`audit/texo-v1/DECISIONS.md`, from `audit/texo-v1/reviews/R1-architecture-review.md` ADR-R6) and supersedes the unreviewed proposal `audit/api/subpath-exports.md`.

HUMAN REVIEW REQUIRED: owner sign-off on the stability labels and allowed peers below. This marker is removed on sign-off.

## Context

The package exposes only `.` and `./package.json` today. The Texo package needs separate entry points for theme, tokens, native and Expo helpers, router adapters, testing helpers and metadata, without exposing internals. The earlier proposal listed `components`, `hooks`, `navigation`, `experimental`, `legacy` and `internal` subpaths; D7 rejected them.

## Decision

The 1.0 export map has exactly these nine keys and no others. `config/exports.json` is the only source of the `exports` field of `package.json` (generated by E14-02; no other ticket edits it). `node scripts/lib/validate-exports-config.mjs` enforces the contract.

| Subpath | Stability | Owned symbols | Rationale |
| --- | --- | --- | --- |
| `.` | stable | 83 | Components, providers and hooks the consumer imports first. Stability is per symbol (ADR 0003), so the root can hold beta symbols without a separate path. |
| `./theme` | stable | 8 | Theme provider, hook and contracts; needed by consumers that build custom themes without pulling components. |
| `./tokens` | stable | 4 | Token factory and types; usable without React Native rendering code. |
| `./native` | beta | 0 | Reserved for React Native-only helpers (no web fallback); symbols are added by later E14 tickets. |
| `./native/expo` | beta | 0 | Reserved for Expo-specific integrations; the only subpath that may declare the optional peer `expo`. |
| `./adapters/*` | beta | 0 | One entry per router or navigation adapter; each adapter declares its own optional peer. The wildcard maps to `dist/adapters/<name>/index.js`. |
| `./testing` | beta | 0 | Test helpers for consumers; kept out of the root so the runtime bundle never includes them. |
| `./meta` | beta | 0 | Machine-readable component metadata (ADR 0016 single source); no runtime UI code. |
| `./package.json` | - | - | Lets tools read the package manifest; the only non-code export. |

Rules:

1. **Conditions.** Every code subpath declares `types`, `react-native`, `import` and `default`. `react-native`, `import` and `default` resolve to the same ESM `.js` file under `./dist/`; `types` is the `.d.ts` next to it. ESM only (D7 asks to confirm this with a spike; the confirmation is not part of this ADR).
2. **Stability is metadata, not path.** A symbol's label (ADR 0003) lives in the metadata; no `./experimental` or similar path exists. The per-subpath stability above is the ceiling for that entry point.
3. **Rejected subpaths.** `./experimental`, `./navigation`, `./components/*`, `./utils` and `./hooks` are rejected: hooks live in the root, components are root exports, and utilities are internal. `./legacy` and `./internal` are rejected too.
4. **Forbidden access.** `src/*`, `dist/*` and any internal path are not exported and are not documented. Deep imports are not public API (ADR 0002).
5. **One primary subpath per symbol.** Every symbol of `audit/api/public-root-api.snapshot` is assigned to exactly one primary subpath in `config/exports.json`. Symbols of `./theme` and `./tokens` are also re-exported from the root during 1.0 (`rootReexports`), so existing root imports keep working; shrinking that list is a breaking change (ADR 0008).
6. **Peers and side effects.** Each subpath lists the peers it may import (`react` and `react-native` required; others optional and only where named). All subpaths are `sideEffects: false` (`audit/texo-v1/spikes/E14-side-effects.md`, recommendation `sideEffects: false`).
7. **Legacy-shim parity.** Every subpath exists identically in the legacy shim (ADR 0013): the shim re-exports each Texo subpath with the same key, so a subpath added here requires the same entry in the shim.
8. **Empty subpaths.** `./native`, `./native/expo`, `./adapters/*`, `./testing` and `./meta` own no symbols yet; later tickets add symbols to the config. An empty subpath is declared in the config but is emitted into `package.json` only if E14-02 decides so (an entry without a built file must not be published).

## Consequences

- Adding, removing or renaming a subpath is a config change plus an ADR amendment and, after 1.0, a semver decision (semver policy, ADR 0011).
- The validator fails on any extra or missing key, forbidden path, condition mismatch, or snapshot symbol that is unassigned or assigned twice.
