# ADR 0013: Legacy shim policy

## Status

Accepted for the D10 items below (`audit/texo-v1/DECISIONS.md` D10, adopted by the orchestrator 2026-10-09, based on `audit/texo-v1/reviews/R1-architecture-review.md` ADR-R9).

The sunset window and the deprecation timeline are tracked in the section "Pending H4" below.

## Context

The future Texo package will replace `@personal-library/react-native-components`. Existing consumers of the legacy name must keep working while they migrate. The legacy package becomes a generated re-export shim of Texo. Nothing in this ADR renames the package, the repository or any import; the rename happens at the cutover (E15).

## Decision

1. **Generated shim.** The legacy package is produced from a generated `dist-shim/` directory that only re-exports Texo. It is generated by tooling from the Texo public surface, never hand-written, and parametrized by the package identity configuration.
2. **Dependency range.** The shim depends on Texo with a caret range of its major version, `^<major>.0.0` (for example `^1.0.0`), not an exact version.
3. **Lockstep versions.** The shim and Texo are released with the same version number.
4. **No install-time or runtime noise.** The shim has no `postinstall` script and emits no runtime warning. Deprecation is communicated through the package metadata and documentation, not through console output.
5. **Global singleton contexts.** React contexts (theme, navigation and any other provider context) are stored as global singletons so that the legacy entry point and Texo share one instance even if both are installed. In development (`__DEV__`) a duplicate-instance condition produces a warning.
6. **`PACKAGE_NAME` is deprecated.** See the section below.

## PACKAGE_NAME

`PACKAGE_NAME` is `@deprecated`. Its runtime value is `"@personal-library/react-native-components"`, the value declared in `src/index.ts` today. The export stays in place with a `@deprecated` JSDoc tag while the legacy name is supported; consumers must not branch on it. The identity configuration, not this constant, is the source of the package name used by tooling. Removal belongs to the deprecation timeline in "Pending H4".

## Pending H4

The sunset window for the shim and the deprecation timeline for deprecated aliases are a human decision (H4 in `audit/texo-v1/DECISIONS.md`).

Recorded owner answer (H4, 2026-10-09, default accepted): the shim sunset is **12 months**, deprecated aliases stay available **through 1.x**, and 1.0 targets Expo 57 / React Native 0.86 only. The calendar start of the 12 months (for example the date of the first stable shim release) and the exact removal date are **not decided** and must be set by the release plan (E17). Until then this section is the reference for the window length only.

## Consequences

- Legacy consumers upgrade to the shim version without code changes.
- Duplicate installs of Texo and the shim cannot split provider state.
- The shim carries no behavior of its own, so parity tests (export parity, type parity, compat suite) are the safety net.
- The caret range lets Texo patch and minor releases reach legacy consumers without republishing the shim, while lockstep versions keep the published pair predictable.
