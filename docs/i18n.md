# Internationalisation

Every built-in string (validation messages, accessibility labels, announcements) lives in one typed catalog, and one
provider supplies the locale, the text direction and your translations. There is no i18n dependency: the catalog is a plain
object and the formatters use `Intl` when the runtime has it.

## Import

```ts
import { LocaleProvider, useMessages, useTranslate, useDirection, useLocale, useFormat } from "<package>/i18n";
```

The `i18n` entry is wired into the package exports by the export wiring tickets; until then import from `src/i18n`.

## Usage

```tsx
const it = {
  "password.show": "Mostra password",
  "password.hide": "Nascondi password",
  "pagination.page": "Pagina {page} di {total}",
} as const;

<LocaleProvider locale="it-IT" messages={it}>
  <App />
</LocaleProvider>;

function Pager({ page, total }: { page: number; total: number }) {
  const t = useTranslate();
  return <Text>{t("pagination.page", { page, total })}</Text>;
}
```

- `messages` is partial: keys you do not set keep their English default (or the value of the outer provider).
- Hoist or memoize the `messages` object; a new object on every render re-renders every consumer.
- Without a provider everything works with the English defaults.

## Catalog

Keys are `<component>.<name>` and are part of the semver surface: a key is never renamed or removed in a minor release,
new keys are added in minors. `{name}` placeholders are filled by `useTranslate()`; an unknown placeholder is left as
written.

| Key | Default |
| --- | --- |
| `validation.required` | This field is required |
| `validation.minLength` | Enter at least {min} characters |
| `validation.maxLength` | Enter at most {max} characters |
| `validation.pattern` | The value is not in the expected format |
| `validation.email` | Enter a valid email address |
| `validation.number` | Enter a valid number |
| `password.show` / `password.hide` | Show password / Hide password |
| `otp.label` / `otp.digit` | Verification code / Digit {index} of {count} |
| `combobox.empty` / `combobox.loading` | No results / Loading results |
| `toast.undo` / `toast.dismiss` | Undo / Dismiss notification |
| `pagination.previous` / `.next` / `.page` | Previous page / Next page / Page {page} of {total} |
| `loading.label` | Loading |
| `dialog.close` | Close dialog |

## Direction

`useDirection()` returns `"rtl"` or `"ltr"`: the `direction` prop of the nearest `LocaleProvider`, else React Native's
`I18nManager.isRTL`, else `"ltr"`. For tests and previews pass `i18nManager={{ isRTL: true }}`. Changing the layout
direction of a native app itself (`I18nManager.forceRTL`) needs an app restart; the provider only reads it.

## Formatting

`useFormat()` returns `formatNumber(value, options?)` and `formatDate(value, options?)` bound to the locale in use. The
standalone `formatNumber` / `formatDate` take the locale as the second argument. When `Intl` is missing (some Hermes
builds) or rejects the locale or options, they return `String(value)` and an ISO date (`YYYY-MM-DD`, UTC) instead of
throwing.
