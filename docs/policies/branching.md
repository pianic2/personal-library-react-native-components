# Branching and commit conventions (Texo V1)

Defined by ADR 0020 (`audit/adr/0020-ticket-execution-protocol.md`).

## Branches
- One branch per ticket, created from `texo/v1`: `texo/PLRNUI-<n>-<slug>`.
- Open the PR to `texo/v1`. Merge into `texo/v1` only with every integration check green and a passing independent review.
- `texo/v1` -> `main` is merged by the PO only. Sessions never push or merge `main`.

## Commit messages
Subject must match `^(add|fix|chore)\(PLRNUI-[0-9]+\): .+`, for example `add(PLRNUI-12): extend a11y helpers`. Merge commits generated by git (`Merge pull request`, `Merge branch`, `Merge remote-tracking branch`) are accepted so a ticket branch can take `texo/v1`.

## Local hooks
Install once per clone (no `package.json` change needed):

```sh
git config core.hooksPath .githooks
```

- `.githooks/commit-msg` runs `scripts/check-commit-msg.mjs` on the commit message.
- `.githooks/pre-push` refuses any push whose remote ref is `refs/heads/main`.

Hooks are a local aid: `git commit --no-verify` or not setting `core.hooksPath` bypasses them. The CI checks of E18-09 and branch protection on `main` are the enforced gate.

Known limitation: git-generated `fixup!`, `squash!`, `amend!` and `Revert "..."` subjects do not match the convention; reword them to `add|fix|chore(PLRNUI-<n>): ...` before committing.

## Branch protection
Applied by the PO in the GitHub repository settings; a session cannot change them.

Required status checks on `texo/v1` (exact names, as shown in the PR checks list):
- `package-baseline` (workflow `CI`, `.github/workflows/ci.yml`)
- `fast-checks` (workflow `Texo V1 PR`, `.github/workflows/texo-v1-pr.yml`): typecheck, tests, script tests, build, docs check
- `commit-and-ownership` (workflow `Texo V1 PR`): commit-message check (`scripts/check-commit-msg.mjs`) on every commit of the PR and file-ownership check (`scripts/check-ownership.mjs`) from the branch name `texo/PLRNUI-<n>-<slug>`

Rules for `texo/v1`: pull request required, the three checks above must pass, no force-push, no deletion. Review approvals are not required, because ADR 0020 has the author session merge after an independent review.

Rules for `main`: changes only through a pull request, no bypass for anyone, no direct push (the local pre-push hook is only a first barrier). Merging `texo/v1` into `main` belongs to the PO.

Ownership exceptions: the backlog JSON is generated and not hand-edited, so files added to a ticket by an explicit PO decision are listed in the `File ownership` step of `texo-v1-pr.yml` (currently `PLRNUI-450`: `skills/texo-execute/SKILL.md`; `PLRNUI-452`: `docs/policies/branching.md`; `PLRNUI-121`: `config/size-limits.json` (the richer motion token set adds about 20 B gzip to the two theme-provider entries of the PLRNUI-208 gate, so those two budgets are raised to the measured size plus headroom; a relaxation of the budget gate flagged to the PO), `ai/manifests/props.json` (the generated props manifest embeds the `Theme` type string of ThemeProvider's `themeOverrides` prop, which includes the motion tokens; regenerated with `npm run ai:build:props`, never by hand) and `tests/theme/theme-contract-v2.test.tsx` (it pins the exact key shape of `theme.motion`, which this ticket redefines; the shape in that test is updated to the new tokens); `PLRNUI-167`: `src/native/core/types.ts`, `src/native/core/noop.ts`, `src/native/testing/mockAdapters.ts` and the two existing tests that pin the closed capability list (`tests/native/core/capabilities.test.tsx`, `tests/native/testing/testing.test.tsx`) and the two type-level contract files that enumerate the closed capability ids (`tests/native/core/contract.types.ts`, `tests/native/testing/mockAdapters.types.ts`), because the ticket requires an `accessibility` capability (the mock capability drives all preference hooks) and the closed `CapabilityMap` needs the new id (same design decision as `PLRNUI-172`, flagged to the PO), and `config/size-limits.json` (the noop api of the new capability adds about 50 B gzip to the `native-core` fixture of the PLRNUI-208 gate, so that one budget is raised to the measured size plus headroom; a relaxation of the budget gate flagged to the PO); the arms for the merged tickets `PLRNUI-201`, `PLRNUI-138`, `PLRNUI-174`, `PLRNUI-134`, `PLRNUI-144`, `PLRNUI-172`, `PLRNUI-178` and `PLRNUI-202` were removed after their merge). The `Execution log` row of `audit/texo-v1/STATE.md` is always allowed.

Trust model: the workflow and the check scripts are read from the pull request head, and no approvals are required, so a PR could weaken its own gates. The independent review (ADR 0020) must therefore read every change to `.github/workflows`, `scripts/check-*.mjs` and the exception list. Exceptions are keyed on the ticket id taken from the branch name and do not expire; remove an entry when its ticket is merged. Branches that do not match `texo/PLRNUI-<n>-<slug>` (for example bot branches) fail `commit-and-ownership` on purpose.
The checks test the pull request head, not the result of merging it into `texo/v1`; bring `texo/v1` into the branch before the final run if other tickets merged in the meantime.
